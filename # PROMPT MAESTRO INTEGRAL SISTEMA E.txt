## 2. ARQUITECTURA DE BASE DE DATOS Y MOTOR DINÁMICO (POSTGRESQL JSONB/GIN)

Implementa en `buses/models.py` la persistencia híbrida, guardando campos estándar en columnas nativas y campos creados desde la web en un objeto `JSONB` indexado:

```python
from django.db import models
from django.contrib.postgres.indexes import GinIndex
from django.contrib.auth.models import AbstractUser

# ── 1. USUARIOS Y ROLES ──
class Usuario(AbstractUser):
    codigo_empleado = models.CharField(max_length=20, unique=True, db_index=True)
    patio_asignado = models.CharField(max_length=100, blank=True)
    cuota_diaria = models.IntegerField(default=20)
    es_admin = models.BooleanField(default=False)

# ── 2. CONFIGURADOR DE CAMPOS DINÁMICOS DESDE LA WEB ──
class ModuloDinamico(models.Model):
    nombre = models.CharField(max_length=50, unique=True) # 'bitacora', 'ee_moviles', 'incidencias'
    descripcion = models.TextField(blank=True)

class CampoConfiguracion(models.Model):
    TIPOS = [
        ('TEXT', 'Texto corto'), ('TEXTAREA', 'Texto largo'),
        ('NUMBER', 'Número'), ('SELECT', 'Lista de opciones'),
        ('MULTISELECT', 'Multi-Selección'), ('BOOLEAN', 'Booleano (Sí/No)'),
        ('DATE', 'Fecha'), ('FILE', 'Adjunto/Imagen')
    ]
    modulo = models.ForeignKey(ModuloDinamico, on_delete=models.CASCADE, related_name='campos')
    clave = models.SlugField(max_length=50) # Key interna JSONB ej: "fase_bocina"
    etiqueta = models.CharField(max_length=100) # Label UI ej: "Fase de Instalación Bocina"
    tipo = models.CharField(max_length=20, choices=TIPOS)
    opciones = models.JSONField(default=list, blank=True) # ["Fase 1", "Fase 2"]
    validaciones = models.JSONField(default=dict, blank=True) # {"min": 0, "regex": "..."}
    requerido = models.BooleanField(default=False)
    orden = models.IntegerField(default=0)

    class Meta:
        unique_together = ('modulo', 'clave')
        ordering = ['orden']

# ── 3. EQUIPAMIENTO EMBARCADO (E.E. MOVILES) ──
class EEMovil(models.Model):
    bus_movil = models.IntegerField(unique=True, db_index=True)
    fase_instalacion = models.CharField(max_length=50, blank=True)
    fase_bocina = models.CharField(max_length=50, blank=True)
    version_firmware = models.CharField(max_length=50, blank=True)
    estado_fw = models.CharField(max_length=50, blank=True)
    
    # Campo JSONB para guardar atributos creados desde la Web
    datos_dinamicos = models.JSONField(default=dict, blank=True)
    actualizado_en = models.DateTimeField(auto_now=True)

    class Meta:
        indexes = [GinIndex(fields=['datos_dinamicos'])]

# ── 4. REVISIÓN Y BITÁCORA ──
class RegistroBitacora(models.Model):
    timestamp = models.DateTimeField(auto_now_add=True, db_index=True)
    bus_movil = models.IntegerField(db_index=True)
    patio = models.CharField(max_length=100, db_index=True)
    tecnico = models.ForeignKey(Usuario, on_delete=models.PROTECT)
    tipo_mantenimiento = models.CharField(max_length=50)
    
    # Respuestas a los campos dinámicos del formulario
    datos_dinamicos = models.JSONField(default=dict, blank=True)

    class Meta:
        indexes = [GinIndex(fields=['datos_dinamicos'])]

3. LOS 7 MÓDULOS DE LA APLICACIÓN WEB
Dashboard y Reportes Avanzados (OLAP Engine):

Selector de rangos de fechas arbitrarios (fecha_inicio a fecha_fin) y agrupadores de período (Diario, Semanal, Mensual, Anual).

Botón de Exportación Asíncrona (CSV / Excel / PDF) procesado en Celery.

Gráficos Recharts:

Reporte de Estado de Componentes: Módems, bocinas, botones de emergencia, SIMs.

Reporte de Incidencias de Móviles: Historial de vandalismo y fallas.

Reporte de Rendimiento de Técnicos: Revisiones realizadas vs cuota_diaria (evaluado con corte de turno a las 08:00 AM).

Reporte de Buses sin Transmisión: Curva de desconexión GPS acumulada.

Bitácora (Bandeja Diaria de Atenciones):

Lista interactiva de incidencias y buses pendientes por atender en el día.

Formulario de revisión que carga dinámicamente los campos nativos + los campos creados desde la web.

Historial de Reportes:

Auditoría histórica completa con filtros multicriterio (fecha, móvil, patio, técnico, estado de componente).

Datos de Genesis:

Servicio en segundo plano para extraer origen, destino, hora de entrada y cálculo de patio de ubicación.

Datos de BUSAE:

Poller asíncrono con Playwright headless para capturar coordenadas GPS en vivo, estado, manos libres y teléfonos.

Datos E.E. Móviles (Equipamiento Embarcado):

Panel de control para hardware embarcado: Fases de instalación, adecuación de bocinas/carcasas, versión de firmware y validadores. Admite campos dinámicos editables desde la App Web.

Usuarios y Roles:

CRUD para técnicos y administradores: Código, Nombre, Patio asignado, Rol y Cuota Diaria.
